# Sticky temporary directories

The pod's fsGroup makes the emptyDir root-owned and mode 2777. Image permissions
are hidden by that mount, and an unprivileged entrypoint cannot chmod its root.
Claude Code 2.1.287 still warns about /tmp even when TMPDIR is private.

A restricted init container creates an owned child directory and sets it to 1777.
Consumers mount that child through subPath at /tmp. The init runs as uid 1000,
with a read-only root, no capabilities and no privilege escalation. Each image
also sets its unmounted /tmp to 1777 for standalone use.

A root init was rejected because it violates restricted admission. Changing only
TMPDIR was rejected because the actual CLI startup still emits the warning.
A CLI-specific socket override would leave the shared temporary mount unsafe.

## Real proof

The real 2.1.287 native CLI first reproduced the reported mode-2777 warning in
an isolated PTY. A disposable k3s v1.34.1 worker then ran manifests generated by
the branch's actual agent and browser factories. Only startup, secret plumbing
and the image were replaced with a stock runtime image and a sleeping process;
the actual init, tmp mounts, pod and container security contexts were preserved.
The exact native CLI was unpacked into the agent's writable home.

Both pods passed restricted Pod Security Admission and ran as uid 1000, with
zero effective capabilities, a read-only root mount and writable /tmp mode 1777.
The real CLI reached its startup prompt without the messaging warning and created
its native /tmp/cc-socks socket. A real Unix client connected successfully. This
proves socket setup and listening, not external-model behavior or delivery to an
owner-authenticated peer session. No provider credentials were used.

The running-pod proof caught GNU chmod preserving the inherited setgid bit with
four octal digits (3777). The final five-digit chmod 01777 explicitly clears it;
the fresh pods then reported exact mode 1777.

Full backend suite with real rootless Postgres 15: 2460 passed, 0 failed, 0 skipped.

Reproduce with the scripts in scripts/proofs/308: bootstrap and start the worker,
install-cluster, run Factory with an output directory, create a tmp-proof namespace
with pod-security.kubernetes.io/enforce=restricted, and apply the generated pods.
Run verify.sh once they are Running. Copy the exact pinned native CLI to
/home/agent/claude.exe and run cli-start.cjs with TASK_ROOT set to the worker state
directory and PROOF_XTERM pointing to the installed headless renderer.
VM disks, SSH keys and raw synthetic screens stay outside Git.
