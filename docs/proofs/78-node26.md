# Align CI and runtime Node versions

Four runtime images already use Node 26; OpenCode and the two CI Node jobs still use 22.
Align those remaining sites on 26 so CI exercises the runtime's actual major version.
A temporary move of every image to 24 was rejected because it would downgrade four images
immediately before 26's scheduled LTS promotion. The coordinator requires this PR to remain
unmerged until 2026-10-28, when 26 is scheduled to become LTS. On 2026-10-27 it is still Current.

Release schedule: https://github.com/nodejs/Release#release-schedule

## Evidence so far

The complete session-agent suite passed under Node 26.12.1: 796 passed, zero failures or skips.
The suite used the image's actual compiled node-pty with production module placement.
The pinned OpenClaw package accepts Node >=25.9.0, the pinned Claude Code package requires
>=22.0.0, and the pinned Codex package requires >=16. OpenCode and Cursor ship native
executables; package engine metadata alone cannot establish their interactive behavior.

The completed interactive and launcher proofs are recorded below; CI supplies clean image
build verification. The PR remains unmerged until the scheduled LTS date.

## Completed local compatibility proofs

`scripts/proofs/78/cli-smoke.cjs` runs every installed launcher in a fresh home and asserts the
runtime pins. Under Node 26.12.1 it passed Claude Code 2.1.287, Codex 0.160.0, OpenCode 1.18.35,
OpenClaw 2026.7.1-2 and the unpinned Cursor build 2026.10.22-27dcf5f. It also used the actual
node-pty 1.1.0 native addon to spawn Node and assert its version and zero exit code.

`scripts/proofs/78/opencode-screen.cjs` passed independently under Node 22.23.4 and 26.12.1:
the actual pinned OpenCode binary reached its provider selector and API-key screen, and the
real runtime detector classified both as credential sign-in. Terminal query replies travelled
through real node-pty. This establishes the changed OpenCode runtime's interactive startup,
not just its version command.

Set `PROOF_CLI_BIN` and `PROOF_CURSOR` for the launcher matrix, and `PROOF_OPENCODE` for the
interactive proof. Run the same scripts with each Node executable; supply the matching native
addon via `PROOF_PTY` when testing an ABI-specific build.

The separate xterm migration proof records all five actual CLI sign-in screens, native model
selection and question screens, plus real Chromium credential and question/free-text round
trips under Node 26. All CLI pins and transport sources are shared between these two changes.
The complete frontend suite passed under Node 26 too: 904 tests across 101 files.

Local container builds were unavailable; clean native builder and image smoke verification
comes from the PR's two-architecture image matrix and runtime CI job. No owner-account login,
external-model call or deployed-cluster behavior was exercised.
