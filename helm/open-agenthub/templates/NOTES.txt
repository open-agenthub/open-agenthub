Open AgentHub {{ .Chart.AppVersion }} is installed in namespace {{ .Release.Namespace }}.
{{- $mode := include "agenthub.authMode" . }}
{{- if eq $mode "oidc" }}

Sign-in: OIDC via {{ .Values.oidc.authority }}.
{{- else if eq $mode "apiKey" }}

Sign-in: API key (no OIDC configured). The UI asks for it once per browser session; it acts
as owner "{{ include "agenthub.apiKeyOwner" . }}", which is always an admin. Read it with:

  kubectl -n {{ .Release.Namespace }} get secret {{ include "agenthub.apiKeySecretName" . }} \
    -o jsonpath='{.data.{{ include "agenthub.apiKeySecretKey" . }}}' | base64 -d; echo

{{- if not (include "agenthub.apiKeyExistingSecret" .) }}

The key was generated by the chart and is kept on upgrades. To rotate it:

  kubectl -n {{ .Release.Namespace }} patch secret agenthub-api-key \
    -p "{\"stringData\":{\"api-key\":\"$(openssl rand -hex 24)\"}}"
  kubectl -n {{ .Release.Namespace }} rollout restart deployment/agenthub-backend

With `helm template` (GitOps) the chart cannot read the Secret back and would generate a new
key on every render: set auth.apiKey.existingSecret there instead.
{{- end }}
{{- if eq (include "agenthub.apiKeyOwner" .) "dev" }}

This release existed before the API key, so the key acts as "dev" — the user every session of
the former unauthenticated mode belongs to. Set auth.apiKey.owner only together with moving those
sessions; docs/no-oidc-api-key.md explains the upgrade.
{{- end }}

For more than one person, configure an OIDC provider instead: --set oidc.authority=https://<provider>/realms/<realm>
{{- else }}

WARNING: INSECURE DEVELOPMENT MODE (auth.insecureDevMode=true). There is no login: every request
is admin user "dev", so anyone who can reach this instance controls every session and secret.
Use it only on a machine nobody else can reach.
{{- end }}
